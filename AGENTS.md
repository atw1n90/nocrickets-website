# NoCrickets Website Repo Notes

## 2026-07-27 Monorepo Merge Findings

- Repo structure change: `nocrickets-website` now contains `/website`, `/onboarding`, and `/shared` on `main`. `/shared` contains `fonts.css`, `tokens.css`, `favicons/`, and `brand-kit/`. The former separate `nocrickets-onboarding` repo was merged into this monorepo. Both site folders reference shared assets with root-relative paths such as `/shared/fonts.css`.
- Deploy dependency: both `/website` and `/onboarding` require the deployed server to expose `/shared` at the domain root. If `/shared` is not exposed, fonts, tokens, favicons, and shared brand assets will 404. The Coolify plan is documented in `coolify-deploy-config-notes.md`: use repo root `/` as the base directory, then use Nginx to serve `/website` or `/onboarding` as the visible site root while aliasing `/shared` from the sibling folder.
- Deploy status as of 2026-09-03: website live checks pass for `https://nocrickets.co/` and `https://nocrickets.co/shared/tokens.css`. Onboarding homepage returns `200`, and its live HTML references `/shared/...`, but `https://onboarding.nocrickets.co/shared/tokens.css`, `/shared/fonts.css`, and `/shared/favicons/favicon-48x48.png` return `404`. This points to the onboarding Coolify container not exposing the sibling `/shared` folder, not a missing source file.
- Current Coolify decision: keep both deployments on repo `atw1n90/nocrickets-website`, branch `main`, base directory `/`. Website Nginx should serve `/usr/share/nginx/html/website` at `/`; onboarding Nginx should serve `/usr/share/nginx/html/onboarding` at `/`; both must alias `/shared/` to `/usr/share/nginx/html/shared/`.
- Current next action: update/restart/redeploy the onboarding Coolify container so `/shared` is present and aliased. Do not return the onboarding base directory to `/onboarding`, because that can make the sibling `/shared` folder unavailable in the deployed image.
